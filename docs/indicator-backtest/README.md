## 1. 方法論

- 對每個訊號定義 Bull（預期漲）/ Bear（預期跌）條件，篩出成立當下的樣本，計算未來 **24 小時**價格是否真的照預期方向走（勝率）。
- **Baseline** = 該幣種同期「無條件上漲機率」（Bear 方向用 `1 - baseline`），代表什麼指標都不看、純粹賭大盤慣性的準確度。
- **Edge** = 勝率 − Baseline，是本報告排名與判讀順序的核心依據。Edge 越高，代表這個指標比單純跟隨當時大盤慣性多帶來的預測力越大。
- 樣本數 N < 30 的訊號標註「⚠ N過小」，僅供參考，不計入可靠度分級。
- **已知限制**：24H 前瞻視窗逐時滑動，相鄰樣本高度重疊（非獨立樣本），與專案既有回測腳本（`analyze_dc_periods.py`、`calibrate_atr_support.py`）手法一致，沒有額外做自相關校正。此外本次資料涵蓋期間大盤偏多頭（BTC/ETH baseline 均 >50%），若進入長期空頭或劇烈盤整，各指標的 edge 可能不同，建議未來資料累積更長後重跑本腳本更新結論。

## 6. 無法回測的部分

- **🗣️ 1H AI 預測**（GitHub Models GPT-4.1）：目前每次通知即時呼叫、不落地存檔，資料庫沒有歷史 AI 預測紀錄可回測。若要驗證其準確度，需先在 `send_tg_notification.py` 把每次的 AI 預測結果連同時間戳寫回 DB，累積一段時間後才能回測。
- **Fibonacci S1 多單進場策略、DC(S) 支撐位緩衝倍數**：已有正式回測結論（見 [交易策略說明](../trading-strategies.md)、[復盤機制](../review-mechanism.md)），計算方式是「進場後多久碰到停損/停利」的事件型回測，跟本報告固定 24H 前瞻視窗的方法論不同，本次不重複驗證，直接沿用既有結論。
- **BB/KC Squeeze**：預測的是「波動壓縮即將突破」而非漲跌方向，不適合放進本報告的方向性排名，如需驗證可另外用「Squeeze 後平均絕對報酬是否比平常大」的方式測試（未來可擴充）。

## 7. 結論

1. 先看 [第 2 節通用版](#2-通用版btceth-合併-逐一指標成效總表) 挑出跨幣種都值得信任的指標；再對照 [第 3 節](#3-各幣種逐一指標成效總表) 確認個別幣種是否一致，把「高可靠」清單放在通知裡優先看。
2. 沒有進到「高可靠」的單一指標，可以查[第 5 節](#5-組合訊號測試誰要跟誰搭配一起看)看有沒有搭配後組合增益轉正——如果組合增益是負的，代表疊加沒有意義，不如只看最強的那個分量就好。
3. 「負向」分級的指標出現時要提高警覺：不是說它一定反著跑，而是歷史上這個方向的判斷還不如瞎猜，不該單獨依賴它做決策。
4. 本報告基於 2026-02 至今、大盤總體偏多頭的資料區間，是否能推廣到空頭/劇烈震盪環境未知，建議之後資料更多時（尤其涵蓋過一次明顯回檔或空頭）重跑本腳本更新結論。
